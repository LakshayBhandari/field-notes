Shadow DOM: the host element still leaks44Com

The 44Com widget mounts into a Shadow DOM so a hostile host page can't restyle it. Shadow DOM is a sealed style scope: CSS outside can't get in, CSS inside can't leak out. So on a page with * { color: red !important; font-family: Comic Sans !important }, the widget's contents render perfectly — !important can't cross a shadow boundary, because it's a different scope, not a specificity fight.

const host = document.createElement("div");
host.id = "widget-44-root";
document.body.appendChild(host);
const shadow = host.attachShadow({ mode: "open" });
// inject widget CSS INTO the shadow root, then render there
render(<App />, shadow);

But the hostile page painted a yellow box with a magenta dashed border around the widget. That box wasn't the widget — it was the #widget-44-root host element itself, hit by the page's div { background: yellow; border: dashed magenta } rule. The shadow root protects its contents; the host element that holds it is a normal light-DOM element the page can still style.

The fix — defend the host element with an inline !important reset, which outranks even the page's !important rules:

host.style.setProperty("all", "initial", "important");
⚠️ IMPORTANT

Common misread: "the widget is inside a shadow root, so it's fully isolated from the page."

Actually: isolation covers everything inside the shadow root, but the host element (the div you called attachShadow on) lives in the light DOM and remains fully page-stylable. You must neutralize it separately — host.style.setProperty("all", "initial", "important"). Plain inline styles lose to a stylesheet's !important; only inline !important (highest in the cascade) wins.

Why it matters: a clean test page hides this — the leak only appears when the host page has aggressive div rules, which is exactly production. Watch inheritable properties too (color, font-family) and prefer px over rem, since rem resolves against the host's root font-size — the last leak vectors through a shadow boundary.
