useReducer actions & payload

An action is just a plain object you hand to dispatch. The reducer is a pure function (state, action) => newState; React calls it for you and stores whatever you return. The type field says which operation; the payload field carries the data that operation needs.

dispatch({ type: 'SET_NAME', payload: 'Lakshay' });

// reducer receives exactly that object:
case 'SET_NAME':
  return { ...state, name: action.payload }; // name === 'Lakshay'

Why read from action.payload instead of hardcoding? Because the same case must work for every value. Without a data slot you'd need absurd separate types like SET_NAME_LAKSHAY, SET_NAME_JOHN. The payload is the argument; the type is the function name. Mentally, dispatch({ type: 'SET_NAME', payload: 'Lakshay' }) is just setName('Lakshay') routed through one central place.

// delete by id — payload carries which one
dispatch({ type: 'DELETE_TODO', payload: 2 });

case 'DELETE_TODO':
  return { ...state, todos: state.todos.filter(t => t.id !== action.payload) };
⚠️ IMPORTANT

Common misread: "type and payload are special fields React requires — like a keyword the reducer engine understands."

Actually: the action object is entirely yours to invent. React/useReducer never inspects it — it just passes whatever you dispatch straight to your reducer as arg 2. You could write { kind: 'add', data: x } or { type: 'add', amount: 5, by: 'user' }. type/payload is convention (popularised by Redux/Flux), not magic.

Why it matters: once you see the action is just a message you design, the contract clicks: the reducer is the only code that reads those fields, so dispatcher and reducer must simply agree on the shape. No framework rules to memorise — you own both ends.
