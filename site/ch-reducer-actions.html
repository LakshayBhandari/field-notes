useReducer, line by line

One small example, dissected piece by piece. Everything useReducer is made of lives in these few lines:

// (1) initial state
const initialState = { todos: [] };

// (2) the reducer: (state, action) => newState
function reducer(state, action) {
  switch (action.type) {            // (3)
    case 'ADD_TODO':                // (4)
      return { ...state, todos: [...state.todos, action.payload] };
    case 'DELETE_TODO':
      return { ...state, todos: state.todos.filter(t => t.id !== action.payload) };
    default:                        // (5)
      return state;
  }
}

// (6) wire it up
const [state, dispatch] = useReducer(reducer, initialState);

// (7) cause a change
dispatch({ type: 'DELETE_TODO', payload: 2 });

Step 1 — the initial state. const initialState = { todos: [] } is just the value state starts as. It can be a number, an object, an array — anything. Here it's an object holding a todos array.

Step 2 — the reducer signature. function reducer(state, action). A reducer is a plain function that always takes exactly two arguments and returns the next state. state = the current value; action = a message describing what happened. You never call this function yourself — React calls it for you (Step 7).

Step 3 — switch (action.type). The action is an object like { type: 'DELETE_TODO', payload: 2 }. action.type is the string that says which change to make, and the switch routes to the matching case. Think of type as the function name you're "calling".

Step 4 — inside a case: build and return NEW state. Take case 'ADD_TODO':

return { ...state, todos: [...state.todos, action.payload] };
  • { ...state } — copy every existing field of state into a brand-new object (so we don't lose todos if there were other keys).
  • todos: [...state.todos, action.payload] — a brand-new array: all the old todos, plus the new one carried in action.payload.
  • You return this new object. Whatever you return becomes the next state. Rule: never edit state directly (state.todos.push(...) is a bug) — always return a fresh copy.

And action.payload is just the data the action carries. type says what to do; payload is the input it needs — exactly like an argument. { type: 'DELETE_TODO', payload: 2 } means "delete, and the id is 2".

Step 5 — the default case. return state unchanged. If an action type doesn't match anything, you must still return the current state (returning undefined would wipe it). It's the safety net.

Step 6 — wiring it up. const [state, dispatch] = useReducer(reducer, initialState):

  • Right side, arg 1: reducer — passed by reference, no parentheses. You hand React the recipe; React decides when to cook.
  • Right side, arg 2: initialState — the starting value.
  • useReducer returns an array of exactly two things. Left side, [state, dispatch], pulls them out by position: slot 0 = current state (read it to render), slot 1 = the dispatch function (call it to change). The names are yours; the order is fixed.

Step 7 — dispatch the full cycle. When you run dispatch({ type: 'DELETE_TODO', payload: 2 }):

  • You don't change state — you just announce the action.
  • React calls reducer(currentState, { type: 'DELETE_TODO', payload: 2 }) for you.
  • The matching case runs, returns new state, React stores it, the component re-renders with the updated state.
⚠️ IMPORTANT

Common misread: writing useReducer(reducer(), initialState) with parentheses, or thinking you call the reducer yourself to update state.

Actually: you pass reducer with no parentheses — a reference, not a call. reducer() would run it immediately (with no args) and pass its return value, which is wrong. You never invoke the reducer in your code at all; the only way it runs is React calling it in response to a dispatch.

Why it matters: this single distinction — pass the function vs. call the function — is the most common useReducer bug, and it's the same idea behind onClick={handler} vs onClick={handler()}. Reference = "here's what to run later." Call = "run it now."
